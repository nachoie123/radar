Radar filling its catalogue, ranking it against a CV and opening a posting. It has sound.

Internship listings live in a hundred career pages, each showing a different slice. Newsletters throw the data away after sending it. Radar keeps one list on your own disk, and tells you which openings match your CV.

Ranked against your CV. No model, no tokens.

Paste your CV once. SQLite FTS5 and bm25() order the Para ti ("For you") tab by match and show the words that hit. Title matches come first.

db.pysearch()
SELECT j.*,
  bm25(jobs_fts, W_COMPANY, W_ROLE, 0.0) AS score,
  bm25(jobs_fts, 0.0, 0.0, 1.0)  AS score_txt
FROM jobs j JOIN jobs_fts
  ON jobs_fts.rowid = j.id
WHERE jobs_fts MATCH :your_cv
ORDER BY (score = 0) ASC,
  score + W_TIE * score_txt

Three files and a database. All standard library.

  1. ingesta.py

    Walks the boards and writes through db.upsert(), nothing else.

  2. db.py + jobs.db

    Every SQL statement in the project lives in one file, and FTS5 lives inside search().

  3. app.py + index.html

    A Python ThreadingHTTPServer on 127.0.0.1 and one HTML file. Nothing is ever exposed to your network.

Install on your Mac. About a minute.

The third step happens only the first time.

Free and open source. Apple Silicon and Intel, 20 MB, macOS 11 or later. The interface is in Spanish.

Or run it from source.

There is no hosted demo, on purpose. Radar holds your CV and your applications, so it runs on your machine at http://localhost:8000 instead of on somebody's server. You need Python 3.9+ with SQLite FTS5, nothing else.

git clone https://github.com/nachoie123/radar.git
cd radar
chmod +x instalar.command Radar.command
./instalar.command      # macOS: sets up the nightly agents and opens the app

# Linux / Windows
python3 ingesta.py      # fills the catalogue (~5 min the first time)
python3 app.py          # serves http://localhost:8000
